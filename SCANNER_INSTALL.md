# Scanner Installation Guide

CodeGauge wraps external scanner binaries. If a binary is missing, you will see scanner failures such as `binary_missing`.

This guide covers:
- generic setup (works across languages)
- language-specific scanner setup
- using the helper script in this repository

## Quick start

From the repository root:

```bash
./install-scanners.sh --profile core
```

Create baseline config files to keep scanners out of `.venv`, `node_modules`, and build outputs:

```bash
./install-scanners.sh --init-config
```

Create configs in another project directory:

```bash
./install-scanners.sh --init-config --target-dir /path/to/project
```

Install everything CodeGauge can auto-install on your machine:

```bash
./install-scanners.sh --profile all
```

Dry-run to preview commands first:

```bash
./install-scanners.sh --profile all --dry-run
```

You can combine install + config init:

```bash
./install-scanners.sh --profile core --init-config
```

By default, config init writes files only if they do not already exist.

## Generic setup

- Ensure these package managers are available when needed:
  - `uv` for Python scanner tools
  - `npm` for JavaScript/TypeScript tools
  - `go` for Go tools
  - `composer` for PHP tools
  - `brew` (macOS) or system package manager for some native utilities
- Java scanners run through your project build tool (`mvn` or `gradle`/`./gradlew`) and JVM plugins.

## Language-specific scanners

## Python

External scanner binaries:
- `ruff`
- `bandit`
- `radon`
- `vulture`
- `pyright`
- `coverage`

Install with `uv`:

```bash
./install-scanners.sh --profile python
```

or manually:

```bash
uv tool install ruff
uv tool install bandit
uv tool install radon
uv tool install vulture
uv tool install pyright
uv tool install coverage
```

## JavaScript / TypeScript

External scanner binaries:
- `eslint`
- `tsc` (via TypeScript)

Install globally with npm:

```bash
./install-scanners.sh --profile javascript
```

or manually:

```bash
npm install -g eslint typescript
```

Note: `npm_audit` and `js_coverage` rely on Node/npm already being present.

## Go

External scanner binaries:
- `staticcheck`
- `govulncheck`

Install:

```bash
./install-scanners.sh --profile go
```

or manually:

```bash
go install honnef.co/go/tools/cmd/staticcheck@latest
go install golang.org/x/vuln/cmd/govulncheck@latest
```

`go_vet` and `go_coverage` use the `go` toolchain directly.

## PHP

External scanner binaries:
- `phpstan`
- `phpcs`

Install:

```bash
./install-scanners.sh --profile php
```

or manually:

```bash
composer global require phpstan/phpstan
composer global require squizlabs/php_codesniffer
```

`composer_audit` requires `composer`.

## Security / Secrets / Infra

External scanner binaries commonly used:
- `gitleaks`
- `trufflehog`
- `opengrep`
- `shellcheck`

Install:

```bash
./install-scanners.sh --profile security
./install-scanners.sh --profile infra
```

On macOS with Homebrew, the script installs:
- `gitleaks`
- `trufflehog`
- `shellcheck`

`opengrep` currently has no universal installer in the script. Install it per your platform and ensure `opengrep` is on `PATH`.

## Java

Java scanners (`spotbugs`, `pmd`, `checkstyle`, `dependency_check`, `errorprone`, `jacoco`) run through your build system and plugins.

Prerequisites:
- JDK
- Maven or Gradle available in the project
- corresponding plugins configured in project build files

The install script checks Java toolchain presence but does not mutate project build files.

## Built-in scanners (no install required)

These scanners run internally and do not need extra binaries:
- `secrets_heuristic`
- `git_history_secrets` (requires `git`)
- framework/infrastructure internal scanners (`django_*`, `dockerfile_scan`, `compose_scan`, `terraform_scan`, `quadlet_scan`, `reverse_proxy_scan`)

## Verify scanner availability

List scanners and whether CodeGauge can use them:

```bash
uv run codegauge list-scanners
```

Run a scan with JSON and inspect per-scanner errors:

```bash
uv run codegauge scan . --json --verbose
```

Look at each `results[]` item for:
- `scanner_name`
- `error_code`
- `error`
- `command`
- `stderr`

## Baseline config files generated by script

When run with `--init-config`, the script creates these files if missing:
- `.codegauge.toml`
- `.ruff.toml`
- `pyrightconfig.json`
- `.bandit`
- `.eslintignore`
- `.coveragerc`

These baseline files prioritize sensible exclusions (`.venv`, `venv`, `.git`, `node_modules`, `dist`, `build`, caches) so scanners focus on source code by default.
